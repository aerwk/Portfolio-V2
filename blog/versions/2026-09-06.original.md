# September 6, 2026

Two revisions shipped today, and the second one exists because the first one was the wrong kind of careful. The morning was a retint: keep the markup, swap the palette and the fonts, delete the leftover decoration, verify every change mechanically. It was thorough — 45 files rewritten, 49 colour literals replaced and counted, fonts checked consistent across 44 pages. Then the review came back: "this is not what i was after. I want none of the old design in the new one." The afternoon was a rebuild from a blank stylesheet, and everything before that sentence is orphaned.

The mistake was believing a retint could be an inspired-by. It can't. A page that keeps its old markup and takes on a reference's colours looks like the reference and is still, underneath, the old page — same bands, same rail, same order the sections fall in. LaunchDarkly's actual contribution as a reference was never its hex values, it was the architecture: banded sections, a persistent rail, a fixed section order, a small vocabulary of components reused everywhere instead of one-off styling per page. Copying colour is decoration. Copying structure is the thing that was actually worth learning.

So the lesson is plain and I'd rather write it down than let it happen again: inspired by X means rebuilding in X's structure, not repainting your own structure in X's colours. The cautious option, keep the markup and change the paint, was the one that wasted the morning.

## What the retint actually did, and why none of it carried over

Rev E, called Control Room while it existed, moved the palette from a violet-glass system to a single accent with a blue for fills, a violet for paint, three neutrals, near-black panels and canvas. Type went from one variable family to a text face plus a mono. Six categories of decorative leftover came out: gradient-border masks, cursor-spotlight overlays, a grain overlay, an inset button recipe, a vignette, every gradient-text treatment. All of it checked, not assumed — literal counts of replaced colours, a page-by-page pass confirming the font links matched everywhere.

None of that verification was wasted effort exactly, but none of it survived either. Rev F, Launch, started from an empty stylesheet and a new HTML skeleton. The home page got rebuilt with the section order locked at About, Portfolio, Blog, Lab, Contact, and that order now cascades through three separate surfaces that have to agree with each other: the nav links, the page flow itself, and the footer's section column. The lab page moved to the same top bar and component vocabulary, with the terminal panel showing real cluster and container status rather than placeholder text. The blog index, all 34 post pages, five portfolio pages and the 404 got re-templated using no new class names at all — every one of them reused the home and lab vocabulary as-is. That's the actual test of whether a design system is real: whether the fortieth page can be built without inventing a fortieth pattern.

## The two numbers that made one accent token become two

The muted label colour sat at 58% lightness against the near-black panel. Measured rather than eyeballed, that's 3.82:1, which fails AA for small text outright. Raised to 60.5%, giving a 5.1:1 minimum with margin. The same accent violet that was fine at large sizes failed at small ones, so a second token had to exist purely for small violet text next to the original. Two tokens carrying one colour is a real tax on anyone reading the stylesheet later, and the honest note here is that nobody went back and checked whether a single lighter token would have cleared both the large-text and small-text thresholds at once. It's a plausible fix that never got tested, which is a different thing from a fix that was tried and failed.

## Two failures that don't show up until you look

Cards were built as anchors, with tag pills inside them that were also anchors. An anchor can't contain another anchor — the HTML parser doesn't error, it just silently closes the outer one wherever it hits the inner one, and the layout keeps rendering as if nothing happened. Hit once on the resource cards, then hit again on the post cards, because the same pattern got reused before the first instance was recognized as a pattern rather than a one-off bug. Fixed both times by moving the click target to the card's container and changing the card itself to a plain `article`.

Separately: `build_blog.py`, the script that generates each new journal post as HTML, keeps its own copy of the page chrome — its own header, its own footer, its own index-card markup, independent of the actual page templates. That copy had to be rewritten by hand alongside the real redesign, because if it isn't, the next post the generator produces regresses straight back to the old chrome sitting inside the new stylesheet. This is a known trap in this repository specifically, and it caught the redesign the same way it's caught other changes before.

## What stayed on the old system on purpose

One surface sits behind an access gate and links the shared stylesheet directly, which meant it would have broken the moment that stylesheet was replaced wholesale. It got frozen to its own copy and repointed mid-redesign, before the public change went out, so the gated page kept rendering correctly through the whole process. It is now deliberately disconnected from the new system rather than accidentally so — a decision made and written down, not a thing that was simply never gotten to.

The last check, run after all 34 posts were re-templated: the prose content of every post had to come out byte-identical to what was there before. Re-templating swaps the frame around the text; it isn't supposed to touch a single word inside it. Confirming that identity is the difference between re-skinning a page and quietly rewriting it, and it's the kind of check that's cheap to run and easy to skip.
