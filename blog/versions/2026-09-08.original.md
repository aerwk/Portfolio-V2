# September 8, 2026

The through-line today was things that only existed in one place. A commit hook that lived nowhere but one machine's `.git/hooks/`. A design source folder the repository was told to ignore, with no history behind it at all. A redesign that could only be seen by a browser if it overwrote the live site. By the end of the day all three had a second home, and the hook is the one worth explaining first, because losing it quietly undoes a fix that was made for exactly that reason.

The site's hero stat tiles pull live container counts over ssh and rewrite three pages' worth of numbers on every commit. That logic has always lived in a `pre-commit` hook, which by design is server-local — nothing in `.git/hooks/` is tracked, cloned, or backed up by the same process that backs up the repository. Earlier this year that hook was rewritten to abort the commit loudly if it can't reach the host or gets back a non-numeric or zero count, replacing an older version that failed silently and let stale numbers ship. That fix was correct. It also has a dependency nobody had written down: an abort-on-failure hook is only as safe as its own survival. A hook that no-ops when it disappears is harmless by construction. A hook that's supposed to stop a bad commit stops nothing once it isn't there, and a missing file doesn't abort anything — it just lets the commit through, which is the exact silent-failure shape the rewrite was built to prevent. The fix and its own precondition were sitting in two different places, and only one of them was tracked.

## Making the hook survive itself

The fix was to stop treating the hook as a fact about one machine and start treating it as a fact about the repository. The hook is now tracked source at `scripts/hooks/pre-commit`, 123 lines, with a README next to it explaining what it does and why it aborts instead of degrading. `.git/hooks/pre-commit` is a symlink into that tracked file rather than a copy, so there's no second version to drift out of sync with the first — editing the hook means editing the one file that's actually in git. It doesn't make the hook run anywhere automatically; a fresh clone still has to install the symlink itself. But it means the hook can be read, diffed, and restored from history instead of being retyped from memory, which is the property that was missing.

## A design folder with no before

The second thing with exactly one copy was less abstract: the entire redesign — logo iterations, stylesheet revisions, the whole design system — lives in a folder the repository has always ignored, on purpose, so design-in-progress never leaks into the tracked site. That's a reasonable rule for what ships. It has a cost nobody had priced: the folder has no history whatsoever. If a CSS change went wrong there was no `git diff` to read and no earlier commit to check out — the only recovery path was last night's vault snapshot, which is a much coarser tool than "the version before the glow went wrong."

The fix was a second, private repository nested inside the working tree, scoped to that one folder. The parent repo still ignores it, so neither repo can see into the other — nothing about the public site history changes. Seventy-seven design files now have real commit history for the first time, and the first push was confirmed by checking the ref on the server afterward rather than trusted because the client exited clean. That distinction mattered on this project before, for an unrelated repository, so it wasn't optional this time.

## A preview instead of a rewrite

The redesign itself went up at `/dev/v3` on the lab host rather than replacing the live portfolio. The alternative — a canary slice of production traffic — got rejected for a plain reason: the design is still changing daily, and a canary implies something stable enough to compare against. A `/dev` path says draft and means it. The mechanics are small: a routing rewrite sends `/dev/*` from the portfolio host to the lab host, `noindex` sits on every page in the preview, and the lab host's robots file now disallows `/dev/` outright. None of that is meant to be clever, just to keep an unfinished design out of search results while it's still visibly unfinished.

Getting the preview tree out of the design source is a 379-line Python generator rather than a hand copy, because hand-copying six pages drifts the moment the source changes twice in an afternoon, and it had already changed more than that today. The generator does one thing worth keeping: it checks its own output before calling the build good. Every internal link gets base-path-rewritten for the `/dev/v3` prefix, and the generator regex-scans the result for anything that wasn't — an unprefixed link would point straight back at the live site from inside a preview page, which is the one failure mode that would be easy to miss by eye and easy to catch by grep. The build fails if it finds one. Idempotency got the same treatment: run the generator twice and diff the output rather than assume a second run changes nothing, because "should be idempotent" and "is idempotent" are different claims.

The same pass pulled the wordmark and a display font out of the markup. Both had been base64-inlined into every page, about 93 KB of it, repeated across all six pages because inlining doesn't cache. Extracted to real files, the shared assets come to about 62 KB total, cached once instead of shipped six times, and the six pages' combined HTML went from 916 KB to 127 KB.

The honest gap is the blog. The preview lists all 34 posts, and exactly one of them has real body content — the rest render from metadata only, because giving all of them the new chrome means teaching the blog generator the new template, and that's deferred to cutover rather than half-done now. Nine navigation tests passed against the deployed preview in a real browser, which covers the chrome. It doesn't cover the posts that aren't there yet.
